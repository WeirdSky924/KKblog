# 任务、运维与质量架构

## 后台任务

Celery Beat 只负责调度，Worker 调用幂等应用服务。任务包括：评论缓冲公开、定时发布、删除冷静期清理、媒体清理、导出包清理、周备份、磁盘检查、Umami 清理和通知聚合。

每项任务记录 `TaskRun`，有幂等键和三次退避重试；最终失败写运行错误并站内通知管理员，不提供网页重试按钮。

## 缓存与一致性

Redis 只缓存公开文章/列表渲染。文章发布、重发、可见性变化、删除和恢复立即失效相关键；评论、浏览量、收藏和通知始终实时读取。Redis 重启后允许短期状态丢失。

## 容器和端口

- SSH 仅使用 444；development/test 的 HTTP 80 只绑定/访问 `localhost`。production 只有在真实域名和必需身份/邮件配置齐全时才公开 HTTP 80 与 HTTPS 443，否则关闭失败。
- PostgreSQL、Redis、Mailpit 和 Umami 不绑定公网端口。
- Compose 服务设置健康检查、依赖就绪和自动重启；Caddy 反向代理 Django。
- `.env` 只在服务器保存，Git 只存 `.env.example`。

## 备份与磁盘保护

- 数据库和媒体在 `Asia/Shanghai` 每周一 03:00（`0 3 * * 1`）同轮备份，首版仅 `local`，保留 30 天；恢复仅服务器手工执行。
- 磁盘低于 10% 告警，低于 5% 禁止图片上传，低于 2% 禁止文字和图片创建；恢复阈值后自动解除。
- 导出 ZIP 三天后清理；Umami 数据一个月后清理。

## 测试矩阵

- Pytest：模型约束、服务、策略、任务幂等、导入导出、媒体生命周期和迁移读回。
- Playwright：访客/用户/作者/管理员关键流程，桌面和手机，弹窗、权限、错误、空态和响应式。
- Ruff：格式、静态质量和 import 纪律。
- 部署验证：迁移前备份、健康检查、失败应用回滚；不自动回滚数据库迁移。

完成声明需要新鲜命令证据，不以原型或静态检查代替真实持久化和用户流验证。
