# K. 工作机会领域

`apps/opportunities` 是招聘来源、岗位、筛选选项、检查历史、审核队列和用户岗位收藏的唯一领域 owner。`administration` 与公开页面只编排其 service/query，不直接写模型、发外部请求或复制筛选规则。

## T20-T23 已建立的事实

- `OpportunitySource`：企业、固定来源类型、无凭据 HTTPS 官方入口、内置适配器 key、安全配置、启用/首次成功公开状态、当前检查摘要和行版本。
- `OpportunitySourceHost`：来源明确允许的规范域名；来源创建时从官方 URL 推导首个 host。
- `OpportunityFilterOption` 与来源观测：城市、类别、届别是全站去重身份；来源观测保留当前可用、首次与最近发现时间。
- `Opportunity`：唯一来源、规范岗位 URL、稳定的规范采集标题身份、来源发布时间、招聘类型、公开字段、核实/上下架状态、逐字段人工覆盖标记、连续失败与来源列表缺失状态；企业名称只从来源读取。同一来源列表 URL 可以承载多个标题不同的独立岗位。`published_at` 只接受来源提供且成功规范化的时间，允许为空，不以采集或更新时间回填。
- `OpportunityFilterAssignment`：岗位可关联多个城市、类别和届别，区分采集值与人工覆盖值。
- `OpportunityCheck`：来源、筛选和岗位 URL 的逐次安全结果，保留 90 天到期时间，不保存响应正文或 Cookie。
- `OpportunityCheckRun` 与来源明细：保存全量/单来源运行、当前来源、汇总计数、安全取消和 TaskRun 引用；PostgreSQL 条件唯一约束保证全站同时至多一个活动检查。
- `OpportunityCollectionSnapshot`：只保存岗位身份/字段哈希、规范筛选项和差异计数；不保存 HTML、原始 URL、Cookie 或页面正文。
- `OpportunityStateTransition`：岗位自动过期与恢复的长期事实，不随 90 天检查历史清理。
- `OpportunityReviewItem`：新岗位、客观字段变化和来源列表缺失的统一待办；开放项按岗位与类型唯一。
- `OpportunityBookmark`：按账户与岗位唯一的私有收藏；管理员不能通过公开或后台通用查询代看。
- `OpportunitySettings` 与 `OpportunityDefaultFilterSelection`：单例设置及城市、核实状态、企业、招聘类型、岗位类别、届别六组多选默认值；默认值只是首次进入时选中的普通筛选条件。

## 写入与读取边界

- 唯一管理员才能创建或管理来源和岗位。新来源默认停用且不公开；首次完整检查成功后才能进入公开来源视图。若来源已存在管理员确认且在架的岗位，后续结构合法但因硬上限截断的采集可以打开或保持公开门禁，可信岗位和本轮新建的待确认岗位继续按普通公开策略展示；来源本身仍保持 `DEGRADED`、截断错误码和筛选陈旧标记，不伪装为完整成功。只有待确认岗位的全新截断来源仍不得公开。
- 管理员手动新建和爬虫新建的岗位都固定为“待确认”、立即公开并进入审核队列；创建入口不能直接设为“已确认”。
- 岗位幂等身份固定为“来源 + 规范岗位 URL + 规范采集标题”。规范采集标题只做 NFKC、连续空白收敛和大小写归一，不做模糊或语义合并；数据库以该 URL/标题二元组的固定 SHA-256 身份键和来源建立唯一约束，避免长 URL 超出 B-tree 索引项上限，规范原值继续保留供匹配和审计。管理员覆盖公开标题或公开 URL 不改变该稳定身份。采集 URL 或规范采集标题真实变化时创建新岗位，旧岗位保留并沿用列表缺失/过期流程。
- 来源和岗位 URL 只接受无凭据 HTTPS；岗位 host 必须在来源 allowlist 中。robots.txt 默认遵守，请求间隔默认至少 2 秒且只能调大。
- `public_opportunities` 只返回启用且已公开来源下，在架、已确认或待确认岗位；DTO 不包含安全错误、allowlist、审核差异或采集内部状态。
- `bookmarked_opportunities(account_id)` 只返回该账户自己的收藏，可保留已下架、已过期岗位并给出公开可理解标记。
- 所有管理写入通过 `opportunities.public` 服务并复用 operations 审计；展示层不直接调用 ORM 写入。

## 管理与公开展示

- `admin:opportunities` 是唯一管理员入口，使用审核队列、岗位、来源、任务历史和设置五个标签页；表单只调用 `opportunities.public` 的管理 service/query。审核队列既可逐条处理，也可原子接受当前页指定项或确认后接受全部开放项；批量服务在数据库中重新锁定仍开放的审核项，并以单次批量审计记录作用域和处理数量。审核、岗位、来源和任务历史必须先在数据库中分页，再把当前页转换为展示 DTO，禁止分页前全量物化。任务历史以 `OpportunityCheckRunSource` 为分页单位，每条明确对应一个招聘来源；逐条详情只在点击时读取该来源的当前与上一份 90 天采集快照，并以身份/字段哈希计算新增和更新岗位，最多展示 200 条且不得在历史列表预加载全部岗位。岗位筛选的各条件组使用共享的可搜索多选 dialog，同组值按 OR 查询、组间按 AND 查询，并统一由“筛选”按钮提交；未选择某组即表示不限。新建和编辑来源/岗位复用原生 dialog，外部检查只创建持久运行，不在 HTTP 请求内同步访问招聘站点。
- 后台一级导航的待办状态来自开放审核计数和失败运行未读通知计数：开放审核项和失败运行复用现有管理导航提醒，不创建第二套通知或计数事实；同一请求复用上下文处理器结果，不在页面 View 中重复统计。
- `opportunities:index` 提供岗位记录与官方来源双视图。岗位筛选同组 OR、组间 AND，覆盖城市、核实状态、企业、招聘类型、岗位类别和届别；每组通过共享的可搜索多选 dialog 编辑，勾选期间不请求，关闭发生变更的 dialog 后只通过 HTMX 刷新一次。管理设置复用完全相同的六组公开选项与多选 dialog，并在无查询参数首次进入时生成普通 URL 筛选参数；关键词和账户私有收藏不进入全站默认值。来源视图按名称和来源类型过滤。岗位关键词搜索只在 Enter 或按钮提交，每页数量即时更新。
- 公开 URL 保存视图、筛选、页码和每页数量，HTMX 替换后恢复滚动和焦点，浏览器前进/后退可重放服务端状态；浏览器不保存第二份岗位或筛选真值。
- 登录账户可在岗位列表幂等收藏并筛选自己的收藏。未登录收藏回跳登录且保留安全同源完整 URL；收藏响应使用稳定外层节点替换、通用反馈事件和现有 Lucide 初始化。
- 页面仅输出公开 DTO 的中文展示标签与公开证据，不展示审核差异、allowlist、安全错误、采集正文或其他账户收藏。
- 公开岗位默认按 `published_at DESC NULLS LAST` 排序，再按企业规范名、岗位标题和稳定 ID 收口；搜索结果先按相关度，再使用同一发布时间顺序。列表明确标注“发布于”或“发布时间未知”，不再把最近核实时间显示为岗位发布时间。

## T21 检查运行时

- 所有外部读取经过同一安全 HTTP owner：只允许无凭据 HTTPS 和来源 allowlist；每跳重新解析 DNS、固定到已验证公网 IP 建连，并重新执行 allowlist、私网/环回/保留地址与 robots.txt 判定。TLS 始终验证原 hostname。
- 整条重定向链最多 5 跳、单次读取总超时 10 秒、普通正文最多 64 KiB；固定内置适配器可按契约显式申请 256 KiB 上限，只有已知的单条异常大记录可申请 384 KiB 绝对上限。同一规范域名的 robots、来源、分页和岗位请求共享至少 2 秒间隔。来源页数默认 50、可由管理员按来源提高到 100，仍受 600 秒来源总时限和 5000 条岗位上限约束。
- 来源只绑定系统内置、版本化 adapter。空岗位/空筛选集合是合法完整结果；截断只写独立 `FILTERS` 事实，不能污染已经成功的 `SOURCE` 可达性事实，也不能推动列表缺失。
- adapter 在每个分页或滚动原子步骤调用受限 heartbeat；达到来源时长软上限时应返回截断，runner 在下一原子步骤前再次强制检查并拒绝继续。浏览器型来源不是通用 fallback，只能使用五个固定 collector；CJS runner 再次校验精确来源路径、允许域名、资源类型、页数、条数与时限，并保持 Chrome 沙箱。Labs 可在同一受限 UID 下本地执行；容器 Worker 只能通过 peer UID、长度前缀和响应上限均受控的 Unix socket 调用独立 `blog-browser` 服务。该服务不持有数据库、Redis 或生产 env，通用 Worker 不获得 `SYS_ADMIN`，也不允许 `--no-sandbox`。
- 完整采集先由 collection owner 按上海招聘学年过滤明确的届别：只保留当届与下一届年份，明确的旧届别、未来届别和非年份届别不进入自动写入；来源没有公开届别时保留岗位并让届别为空，不猜测或伪造年份。每年 7 月切换年份窗口。新岗位固定待确认并进入审核队列。岗位 URL 按上海自然日连续两次失败才自动过期，同日重复失败不累加；恢复后回到待确认并写长期状态转换。
- 全量与单来源手动请求、每日上海时间 18:00 调度共用同一幂等运行服务。启用新来源使用 `activate_source_and_request_check`，启用与首次运行创建同事务提交；broker 首次派发失败由每分钟有界扫描 `PENDING` 运行补偿。
- 每分钟 `recover_check_leases` 先通过 operations owner 回收过期 `run_check` TaskRun 租约，再把中断的来源明细从 `RUNNING` 恢复为 `PENDING`；重试窗口到期后重新派发原运行。第三次租约失效将当前来源标为失败、其余来源标为未执行并终结旧运行，沿用统一 TaskRun 最终失败告警。每日 18:00 调度复用活动运行前先执行同一恢复，不能把失效的 `RUNNING` 当成活动事实。
- 回收事务同时记录 `opportunity.check_stalled.v1`：租约过期按尝试次数去重告警，来源明细超过其 `max_duration_seconds` 时记录一次超时告警；事件只携带运行编号、来源展示名、位置和安全状态，不携带响应正文或连接信息。
- 全量任务按来源串行；安全取消在来源原子步骤之间生效，未处理来源标为 `NOT_EXECUTED`，业务运行与通用 TaskRun 均进入 `CANCELLED`，不产生最终失败通知。
- 每天上海时间 18:30 小批量清理已到期检查和结构化快照。来源首次失败、进入过期、恢复及有异常/变更的运行汇总通过现有 Outbox 和通用通知中心投递管理员。
