# 数据、安全与生命周期

## 数据分层

| 位置 | 保存内容 | 生命周期 |
| --- | --- | --- |
| PostgreSQL | 用户、文章正文、版本、草稿、权限、评论、举报、通知、审计、导入导出元数据 | 业务规则定义，不能依赖缓存 |
| 媒体目录 | 封面、正文图、头像、评论图、证据图、导出包 | 文件必须有归属记录与清理任务 |
| Redis | 验证码、冷却、限流、公开渲染缓存、短期聚合键 | 可随重启丢失 |
| `var/backups` | 每周数据库与媒体备份 | 30 天、本地、不加密 |
| Umami 数据库 | 全站分析 | 一个月后清理 |

## 主聚合

- `Account`：不可复用的内部 UUID、邮箱、昵称、角色、状态、主题偏好。
- `LoginSession`、`InviteCode`、`IpBlock`、`SecurityEvent`：持久认证与追踪；验证码、限流和冷却只在 Redis。
- `Article`：公开 ULID、作者、发布状态、工作/发布/定时修订指针和删除状态。
- `ArticleRevision`：完整正文、格式、可见性、分类、媒体和评论设置快照。云草稿也是当前工作修订；恢复生成新修订。
- `Section`、`Tag`、`TagProposal`：一对多分区和最多十个标签。
- `MediaAsset`：拥有者、用途、内容哈希、真实格式、路径、引用和删除状态。
- `DiscussionThread`、`Comment`：文章/留言板共用树、缓冲、删除占位和排序投影。
- `Report`、`ReportAppeal`、`ArticleModerationCase`、`ArticleAppeal`：审核、一次申诉、管理员遮罩和证据。
- `Notification`、`NotificationReceipt`：群发、事件通知、已读和聚合。
- `AuditEntry`、`RuntimeError`、`TaskRun`：永久可追溯运维记录。
- `ImportJob`、`ExportJob`、`BackupRecord`：异步数据交换和运行维护。

## 生命周期规则

- 文章删除先软删除 7 天，恢复原记录；到期物理删除正文、修订、媒体、评论和评论图，保留审计、举报和申诉记录。
- 管理员隐藏是独立覆盖层，不修改作者原可见性；仅管理员可恢复。作者禁用隐藏文章，重新启用自动恢复原可见性。
- 作者草稿默认仅作者可见；唯一管理员有只读例外，查看他人草稿/未发布修订时每篇每天至多一条作者通知。管理员不能编辑或发布。
- 媒体上传验证签名并去 EXIF；正文解除引用或评论删除时立即清理，删除任务必须幂等。
- 账号删除移除私有资料、文章和媒体；评论保留删除占位；举报与审计记录保留并显示管理员所需身份信息。

## 服务端权限矩阵

| 动作 | 普通用户 | 作者 | 管理员 |
| --- | --- | --- | --- |
| 公开/登录文章阅读 | 允许 | 允许 | 允许 |
| 私人文章阅读 | 禁止 | 仅自己的 | 全部，通知作者 |
| 文章编辑/发布 | 禁止 | 仅自己的 | 自己的可按作者身份；他人的禁止 |
| 文章隐藏/恢复 | 禁止 | 可改自己的可见性 | 已发布文章专属隐藏/恢复 |
| 文章删除/恢复 | 禁止 | 仅自己的 | 全部，通知作者 |
| 评论/举报 | 已登录可用 | 已登录可用 | 全部管理 |
| 草稿查看 | 禁止 | 仅自己的 | 可查看，通知作者 |
| 管理设置/导出 | 禁止 | 禁止 | 唯一管理员 |

所有矩阵判断必须通过策略对象和服务端服务执行。直接 URL、HTMX 片段和 Celery 任务使用同一策略。

## 安全边界

- 密码、令牌、验证码、连接串从日志、审计和错误页面完全脱敏。
- HTML/Markdown 使用统一 allowlist，禁止脚本、事件属性、危险协议和未批准嵌入。
- 图片最大 2 MiB，并执行 `DEC-005` 静态/动图解码上限；外部嵌入只有管理员配置的 Bilibili 初始来源。
- 邮箱和 IP 限流以 Redis 实现；永久 IP 封禁保存在 PostgreSQL。
- Cookie 使用安全、HttpOnly、SameSite 策略；生产 HTTPS 后强制 Secure。

完整字段、索引与保留规则以 `data/` 为准；完整管理员例外和对象状态权限以 `contracts/02-authorization-matrix.md` 为准。
