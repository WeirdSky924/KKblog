# ADR-002：PostgreSQL 正文与不可变修订

状态：Accepted

## Context

正文需要草稿、定时发布、旧版本继续公开、完整历史、冲突处理、恢复和导入覆盖。把正文放文件、数据库只存路径，会造成数据库事务与文件替换不一致，备份/恢复和搜索也跨两个事实来源。

## Decision

正文、TipTap JSON、Markdown、修订、草稿指针、发布指针和权限全部保存在 PostgreSQL。每次显式云保存创建不可变 `ArticleRevision`；`Article` 分别指向 working、published 和 scheduled revision。

媒体保存在文件系统，正文只引用受控 media ID。Redis 仅缓存已清洗公开渲染，不保存唯一正文。

## Consequences

- 发布和回滚是原子指针切换；读者不会看到半保存正文。
- 数据库增长更快，但纯文本/JSON 对私人博客规模可控，备份语义清晰。
- 版本冲突、历史恢复和导入都复用同一修订模型。
- 需要控制默认 `2 MiB`、可配 `64 KiB..2 MiB` 的序列化正文上限，建立合适索引，并禁止把正文复制到审计/事件。

## Rejected alternatives

- 正文文件 + 数据库路径：双写一致性、并发和备份复杂。
- 只保存最新正文：无法满足完整历史和恢复。
- Redis 正文缓存为事实：重启会造成数据丢失。

## Revisit when

真实数据库体积、备份窗口或正文 I/O 指标达到已测瓶颈时，先评估分区/归档/压缩；仍不足才设计带校验和与事务清单的外部对象存储。
