## 需要保持的差异

- 账户禁用：历史评论继续显示；已发布文章全部隐藏，启用后自动恢复；定时文章转草稿且不自动恢复排期。
- 评论删除：一般保留占位；文章永久删除时评论/回复/图片物理删除，报告/申诉/审计保留。
- 管理员隐藏与作者可见性：隐藏是独立遮罩，不把文章 visibility 改为 PRIVATE。
- 通知隐藏与删除：两者用户均不可见；隐藏可恢复，删除不可由产品界面恢复，但审计保留。
- 备份成功：只表示备份命令成功与文件生成；当前明确不做完整性校验或恢复演练。

## 架构自行确定的实现口径

以下没有改变产品行为，是为保证一致性补充的工程决策：

- Account 内部 ID 使用 UUIDv4；Article/Revision/Comment/Job 使用 URL 安全 ULID。
- 邀请码原码只在生成时显示一次，数据库保存带密钥摘要和尾号，避免历史泄露。
- 文章显式云保存产生不可变修订；published/working/scheduled 用指针分离。
- 跨领域副作用使用事务 Outbox；Redis 不承担永久锁或事实状态。
- 导出富文本历史保留 TipTap JSON 原始源，Markdown 仅为方便副本，避免宣称无损转换。
- 评论举报初审删除对外占位，申诉终局前恢复材料只在审核域受限保存。

## 尚未产品化的保留空间

以下保持扩展边界但首版不制作：

- 公共 API、移动 App API、第三方登录、RSS、点赞、社交平台直发。
- 除 Bilibili 外的可信嵌入来源，可由管理员未来配置。
- 除中文外的界面语言；错误码与文案已分离以便未来本地化。
- 外部备份目标；保留 destination port/config，首版只写本地。
- 举报之外的新评论管理 tabs；前端 tab 容器可扩展但不放空入口。
- 生产域名和 HTTPS 实值；Caddy 结构预留，development/test 只使用 `localhost`，production 缺必需实值时关闭失败。

## 需求变更方法

新增或修改需求时不要直接改散落文档。先在访谈/变更记录追加新决策并写明覆盖对象，然后：

1. 更新本文覆盖关系。
2. 更新受影响 ADR（新建取代 ADR，不抹去旧理由）。
3. 更新字段/状态机/权限/服务/前端契约。
4. 更新验收矩阵与实现切片。
5. 在代码阶段用失败测试固定新口径。
