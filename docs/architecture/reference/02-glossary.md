# 架构术语表

| 术语 | 在本项目中的含义 |
| --- | --- |
| 领域所有者 | 对一类业务事实拥有唯一写入口的 app，例如 content 拥有文章生命周期 |
| 聚合 | 必须在一个事务边界内保持一致的一组对象，例如 Article 与它的修订指针 |
| 应用服务 | 执行授权、事务、锁、审计和事件的命令入口，不是杂项业务函数集合 |
| Policy | 对 actor、对象与状态作服务端授权/能力判断的纯规则 |
| Query | 面向具体读取场景、已包含可见性过滤的读取入口 |
| DTO | 跨层传递的明确数据形状，不把 ORM/HttpRequest 泄漏到其他层 |
| 不变量 | 无论从网页、任务还是命令进入都必须成立的规则，优先由数据库和服务共同保护 |
| 不可变修订 | 创建后不原地更新的 ArticleRevision；新保存产生新记录 |
| 工作修订 | 作者当前编辑/云草稿对应的 revision |
| 发布修订 | 当前读者可见的 revision；编辑期间保持不变 |
| 遮罩 | 不改原业务值、但让查询暂时不可见的独立状态，如管理员隐藏/作者禁用 |
| 软删除 | 记录暂时保留且可恢复，本项目文章为 7 天 |
| 物理删除 | 从业务表和媒体目录永久删除；审计/案件可按规则保留 |
| Outbox | 与业务事务一起写入的待发布事件，解决提交与外部副作用之间的崩溃窗口 |
| 幂等 | 同一业务意图重复执行，最终效果与执行一次相同 |
| 幂等键 | 标识同一业务意图的稳定键，不等同于 Celery 临时消息 ID |
| 条件更新 | 只从期望旧状态更新到新状态，重复执行影响 0 行 |
| 行锁 | PostgreSQL `SELECT FOR UPDATE`，用于序列化同一聚合的并发写 |
| 部分唯一索引 | 只对满足条件的行唯一，例如全站最多一个 RUNNING 导出 |
| 数据投影 | 为读取性能维护的派生表/列，如 ArticleTag；事实仍由修订和服务维护 |
| Saga | 跨数据库与文件系统等无法单事务时，用可重入步骤和补偿收敛 |
| Capability flag | 服务端策略返回给模板的可显示动作；它不能替代提交时重新授权 |
| 事实来源 | 发生冲突时具有最终裁决权的数据；本项目业务事实是 PostgreSQL |
| 可丢失状态 | 丢失只影响体验、不破坏正确性的缓存/验证码/冷却等 Redis 数据 |
| Trace code | 给用户的安全问题编码，用于管理员检索脱敏诊断链 |
| ADR | 架构决策记录，保存背景、结论、代价和何时重评 |
| Expand/Migrate/Contract | 先加兼容结构、再迁数据/切读写、最后移除旧结构的迁移方法 |
| Keyset 分页 | 用最后一条稳定排序键继续查询，适合评论/通知/日志无限加载 |
| HTMX partial | 同领域返回的局部 HTML，不是隐式公共 JSON API |
| 终稿预览 | 发布/恢复前必须经过的完整文章审查阶段，不等同编辑器实时预览 |
| 未知分区 | 分区删除或导入无法映射时的空外键状态，只在首页/标签可发现 |

学习时遇到陌生词先回到“它保护了哪条产品规则”。如果一个架构术语不能解释对应风险或行为，很可能只是装饰性抽象。
