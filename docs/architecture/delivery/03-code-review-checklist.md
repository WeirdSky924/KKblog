# 架构与代码评审清单

这份清单用于实现前设计评审和实现后代码评审。它不是打勾仪式；每个“是”都应能指向代码、迁移、测试或运行证据。

## 1. 需求与边界

- 当前行为能指向访谈决策、状态机和页面契约。
- 后确认决策已覆盖旧表述，没有把 5 MB、IP 白名单或草稿权限旧结论重新实现。
- 明确写出范围内、范围外和失败行为，没有用“未来再做”遗漏必要闭环。
- 用户动作的入口、身份、结果、错误和数据读回完整。

## 2. 所有权与复用

- 能回答该事实的唯一 owner app；没有第二套权限、媒体、通知、缓存、重试或错误体系。
- `authoring`/`administration` 只编排，不拥有内容、账户或审核事实。
- 跨 app 只调用公开 service/query/event；没有直接修改他域 ORM 私有模型。
- 新抽象至少消除真实重复或稳定契约，不是仅为“看起来像架构”。

## 3. 分层

- View 只做 HTTP/表单/响应，不包含跨实体事务或角色判断。
- Service 承担授权、事务、锁、审计、outbox；不依赖 HttpRequest/模板。
- Query 明确 actor 与可见性，不暴露无过滤 `all()` 给页面。
- Model/constraint 保护稳定不变量，不承载跨领域流程。
- Celery task 只重入 service，重复执行有相同结果。

## 4. 数据与迁移

- 主键、外键、唯一、检查、部分唯一和索引与字段字典一致。
- 时间 UTC 存储，上海自然日只在边界转换。
- nullable/default 有明确语义，没有用空字符串/魔法值混淆未知状态。
- 删除、恢复、历史、媒体和审计的级联/保留策略明确。
- 迁移说明锁、回填、兼容、备份、应用回滚与读回。
- JSON 只承载有 schema 的快照/payload，不替代关系。

## 5. 认证、权限与隐私

- 服务端按 IP、会话、账户、角色、对象、生命周期、容量顺序重判。
- 私人/草稿对象对无权者使用 404，不能通过错误差异推断存在。
- 管理员例外仅为查看/隐藏/删除/恢复，不意外扩展到编辑/发布。
- 管理员查看通知、举报人隐藏、完整 IP 详情权限均有测试。
- 密码、码、token、Cookie、连接串、正文和上传内容不进入日志/事件。
- 管理员写命令审计与业务事务同成败。

## 6. 并发、异步与外部副作用

- 明确幂等键、锁对象、允许的重复投递和最终状态。
- 数据库唯一/条件更新是最终裁决，Redis 锁不是事实来源。
- 外部邮件、文件删除、任务投递在事务提交后执行或由 outbox 驱动。
- 三次失败、最终错误、通知与无网页手动重试行为一致。
- Worker 崩溃、超时、重复、取消和对象中途变化都有处理。

## 7. 前端与可访问性

- 页面/partial 使用同一 DTO 和服务，不存在第二份前端业务规则。
- pending、422、409、500、空、禁用、取消、重试和成功状态均设计。
- 弹窗焦点、键盘、Escape、重复提交、关闭恢复符合约定。
- 1440/390、三主题、长文本和管理表格均真实浏览器检查。
- UI 成功反馈只在真实持久化/Job 完成后出现。

## 8. 文件与命名

- 文件名按能力命名，无 `misc`、`helpers2`、`common_new`、万能 utils。
- 接近 800 行说明职责仍聚焦；超过 1,200 行新增行为前已拆分。
- 命令为动词、查询为问题/名词、事件为过去式并有版本。
- 公共 API 有真实消费者；私有实现没有被跨 app 导入。
- 注释解释约束与原因，不复述代码。

## 9. 测试证据

- 逻辑变更有先失败的聚焦测试，失败原因就是目标缺失。
- 权限/版本/删除/任务/交换包含真实 PostgreSQL 读回。
- 文件行为使用临时隔离目录，不污染 `var/` 或用户数据。
- Playwright 走真实用户入口并观察可见结果/后端读回。
- 当前改动后重新运行了决定性命令，报告退出码和未执行项。

## 常见架构异味

| 异味 | 说明 | 修正方向 |
| --- | --- | --- |
| View 内多次跨域 `.save()` | 事务/授权散落 | 提取到 owner service |
| 管理页面直接改模型 | 绕过审计与事件 | 委托正式命令 |
| Task 复制一段业务 ORM | 重试路径行为漂移 | Task 调可重入 service |
| `if user.is_admin` 到处出现 | 权限体系平行 | 集中 policy/capability |
| 任意 `target_type`/JSON | 无 schema、无引用安全 | 注册表 + schema + 服务校验 |
| Redis 键决定永久状态 | 重启丢事实 | PostgreSQL 为事实，Redis 优化 |
| UI 提前 toast 成功 | 用户认知与事实不一致 | 等数据库/Job 终态 |
| 为测试加静默 fallback | 掩盖真实缺失 | 使用隔离 fixture/显式失败 |

## 评审输出

评审先列问题，按严重度排序并引用文件/行；随后写开放问题与假设；最后才写变更摘要。没有问题时也说明测试缺口和残余风险，不使用“看起来没问题”代替证据。
