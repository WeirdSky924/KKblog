# 存储布局、缓存与数据生命周期

## 服务器目录

```text
/home/code/personal-blog/
  .env                         # 服务器直接维护，不入 Git、不提供网页编辑
  var/
    postgres/                  # PostgreSQL volume
    redis/                     # 可丢失；不依赖持久化恢复
    media/
      users/<user-id>/
        avatar/
        articles/<article-id>/
          cover/
          body/
          attachments/
          comments/
          evidence/
        imports/<job-id>/
      site/
        brand/
        friend-links/
    exports/<export-job-id>/   # 生成中与完成 ZIP，最多三天
    backups/<backup-id>/       # 数据库+媒体周备份，30 天
    logs/                      # 容器/应用输出，由轮转策略控制
```

数据库只保存相对 `storage_key`。任何请求都不能把上传文件名、邮箱、昵称或客户端路径拼进磁盘路径。下载和私有媒体读取必须经媒体授权服务，Caddy 只对明确公开的不可变资产使用受控内部跳转。

## 上传两阶段协议

1. 请求层检查磁盘保护门禁与 Content-Length，但不把它视为最终校验。
2. 流式写入同一文件系统的 staging 临时文件，图片限制 2 MiB、文章附件限制 10 MiB，并计算 SHA-256。
3. 图片解码真实格式、检查像素维度、去 EXIF/元数据；GIF 逐帧安全重编码并保留动画。
4. 校验用途允许格式：普通图片 PNG/JPEG/GIF/WebP；Logo PNG/ICO；文章附件 ZIP/7z/RAR/UTF-8 MD/TXT，并按压缩签名或文本编码复核内容。
5. 数据库事务创建 `MediaAsset(STAGED)` 与业务绑定意图。
6. 事务提交后原子移动到最终 `storage_key`，再标记 `ACTIVE`。
7. 移动失败写运行错误并安排幂等补偿；STAGED 资产不可被页面引用。

正文预览使用短期上传资产。作者保存云草稿或发布时，内容服务提交解析后的媒体 ID 列表和零或一个附件 ID，媒体服务在同一业务命令中核对所有权、用途、固定槽位和文章归属后绑定。不能从 HTML 中信任任意 URL 作为站内媒体引用。

## 删除协议

- 正文图片解除引用、评论删除、证据清理：事务中把 Binding 删除并将无引用资产标为 `DELETE_PENDING`；提交后立即尝试删文件，失败交给任务重试。
- 文章软删除 7 天：所有媒体继续保留但不可公开读取。
- 文章到期清理：数据库聚合删除与媒体待删清单在事务中确定；文件删除可重入，路径不存在视为成功。
- 账户删除：先处理作者文章，再删除头像、导入暂存和私有资产。
- 导出 ZIP：任务取消立即标待删；完成后三天到期删除；审计和 Job 记录不删。

永远不要“先删文件再提交数据库事务”，否则事务失败会留下不可恢复的断引用。

## Redis 键空间

| 键前缀 | 内容 | TTL/清理 |
| --- | --- | --- |
| `verify:{purpose}:{email-hash}` | 验证码摘要、失败次数、签发时间 | 10 分钟；重发覆盖旧值 |
| `verify-send:email:{date}:{hash}` | 上海自然日发送次数 | 下一次上海 00:00 |
| `verify-send:ip:{date}:{ip-hash}` | 上海自然日 IP 发送次数 | 下一次上海 00:00 |
| `login-fail:{email-hash}` | 连续密码失败数 | 成功后删；第 5 次转限制 |
| `login-block:{account-id}` | 一小时访问限制 | 1 小时或管理员删除 |
| `comment-cd:guest:{ip-hash}` | 访客评论冷却 | 5 分钟 |
| `comment-cd:user:{user-id}` | 登录评论冷却 | 1 分钟 |
| `cache:article:{id}:{revision}` | 公开文章静态渲染 | 版本化键 + 主动失效 |
| `cache:list:{query-hash}:{generation}` | 公开列表片段 | 短 TTL + generation 失效 |
| `alert-dedupe:{fingerprint}` | 同一持续故障邮件限频 | 1 小时 |

邮箱/IP 在 Redis 键中使用服务端 HMAC，不写明文。Redis 丢失只会使验证码、冷却和缓存提前失效，不得造成永久权限提升或业务数据丢失。

## 缓存边界

只缓存公开文章正文的已清洗渲染结果和公开列表的静态字段。以下数据不进入页面缓存：评论、浏览量、收藏状态、通知、账户菜单、管理员遮罩、作者禁用状态。

页面组装顺序是：先用服务端策略确认当前已发布修订仍公开，再取对应 revision 缓存；动态区域单独查询/HTMX 获取。发布、重发、可见性变化、标签/分区变化、隐藏、删除、恢复和作者禁用/启用都会增加相关 generation 或删除明确键。

## 生命周期表

| 数据 | 活跃期 | 逻辑删除 | 物理删除/保留 |
| --- | --- | --- | --- |
| 账户 | 启用/禁用 | 无自助冷静期 | 管理员确认后删除；历史身份快照保留 |
| 文章 | 草稿/定时/发布 | 7 天 | 到期正文、修订、媒体、评论物理删 |
| 修订 | 文章存在期间永久 | 不单独删除 | 随文章物理删除 |
| 评论 | 缓冲/可见 | 删除占位 | 随文章物理删除；举报审计保留 |
| 标签 | 待审/全站 | 拒绝或管理员删除 | 记录永久保留以支持历史/恢复 |
| 通知 | 可见/已读 | 管理员隐藏或删除 | 业务记录与审计永久，用户查询排除 |
| 审计/错误 | 永久 | 无 | 永久，按脱敏规则保存 |
| 导入源包 | 预览/执行 | 完成或取消 | 任务结束后清理源文件，Job/Item 保留 |
| 导出包 | 完成后可下载 | 取消/过期 | 三天删除 ZIP，Job/审计永久 |
| 备份 | 可用于手工恢复 | 到期 | 30 天删除归档，记录保留 |
| Umami | 分析查询 | 到期 | 一个月清理 |

## 磁盘保护

磁盘状态是运维服务计算的运行门禁：

- 可用空间低于 10%：站内与管理员邮件告警，每个持续故障每小时最多一封。
- 低于 5%：拒绝所有新图片，提示“暂时不支持上传图片”。
- 低于 2%：拒绝所有文字和图片创建；既有内容继续只读。
- 回升越过对应阈值后自动解除，不发恢复邮件。

检查必须位于所有写入服务的统一 `CapacityPolicy`，不能只禁用前端按钮。数据库必要的审计/错误记录应保留最低写入通道，避免保护模式反而失去诊断能力。
