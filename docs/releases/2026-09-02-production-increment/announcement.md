# Kaj 空间正式增量更新公告（候选）

状态：候选准备中，尚未执行正式环境切换。正式发布时间、候选提交、镜像摘要、迁移和健康检查结果需在部署完成后由执行记录补充。

本次更新从上一正式基线 `d8aaba9` 前向增量发布，保留现有账户、文章、评论、通知、媒体、岗位和答题数据，不复制 Labs 数据，不清空生产数据卷。

## 主要更新

- 公开作者主页和文章列表查询增加批量统计与条件索引，减少大列表加载开销。
- 通知中心使用局部响应和合并未读查询；右上角通知浮窗按内容自然撑开，不再出现内部滚动条。
- 标签筛选、文章目录、阅读书签、点赞和文章动作继续复用现有组件与权限策略。
- 分析采集路径修正为站点根路径，避免重复的 `/analytics/analytics/collect` 请求。
- 招聘检查恢复流程加强 PostgreSQL 断连、过期租约和孤儿运行协调，避免每日 18:00 任务被失效运行永久阻塞。
- 新增文章公开列表和通知可见时间索引：`content.0017`、`notifications.0002`。

## 数据与招聘采集

本次发布不迁移 Labs 的岗位、采集快照、审核、收藏或任务历史，也不在发布窗口手动抓取招聘来源。来源采集仍由既有 Celery 计划任务触发，系统会分别记录成功、失败、截断和岗位数量。

若正式数据库存在历史失效的招聘检查状态，候选 Worker 启动后先运行有界恢复入口，确认租约、来源明细、领域运行和 TaskRun 终态一致，再恢复每日调度。无法安全归属的状态不会被静默删除。

## 发布与回退

正式执行前需要新鲜数据库/媒体备份（仅在有待迁移时强制）、迁移计划核验和维护窗口。若候选应用不健康，只恢复已记录的旧应用镜像，数据库保持前向结构，不执行反向迁移或删除生产数据。

正式部署完成后将补充候选 SHA、镜像摘要、备份摘要、迁移 leaf、状态修复计数、健康读回和剩余风险。
