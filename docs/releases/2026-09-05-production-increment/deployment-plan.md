## 发布前门禁

1. 从已核验的远端 `main` 祖先创建候选，逐路径核对 Labs 修改和新增文件。
2. 排除 `.env`、`.venv`、`var/`、数据库、媒体、日志、缓存和一次性测试文件。
3. 串行执行 Ruff、Django check、模型漂移检查、前端构建、契约回归和生产配置预检。
4. 读取正式 `migrate --plan`；无待执行迁移时跳过 migration，不执行反向迁移。
5. 创建新鲜 PostgreSQL dump、媒体归档和运行配置副本，校验权限、SHA-256、路径和 `pg_restore --list`。

## 应用切换

1. 开启 Nginx 维护响应并从公网验证 503；暂停 Web、Worker、Beat 写入。
2. 以同一候选镜像重新创建 Web、Worker、Beat，先验证 Web/Worker 健康，再恢复 Beat。
3. 执行 `collectstatic --noinput`，禁止 `--clear`，验证 CSS、JS、字体和媒体读取。
4. 通过现有 `apps.opportunities.recover_check_leases` 入口执行一次有界恢复，不直接调用 adapter。
5. 通过现有 `publish_outbox` 入口处理积压，读回事件状态和消费者幂等状态。
6. 恢复 Beat 周期调度，读回招聘恢复、补偿、Outbox 和健康检查任务日志。
7. 关闭维护响应，串行验证健康端点、主要页面、静态资源、媒体资源和匿名权限流。

## 状态修复与回退

- 活动运行、运行中来源、过期租约、待发布 Outbox 或处理中消费者不为零时，停止发布并保留证据。
- 候选应用不健康时只回退 Web、Worker、Beat 镜像；本轮无数据库迁移，不反向迁移。
- 旧镜像、数据库 dump、媒体归档和 Compose 配置副本必须保留，不得用 `latest` 作为唯一回退依据。
