# 正式状态修正 Runbook

本文件是合并发布目录的状态修正操作说明。所有命令必须限定到正式项目服务、正式数据库和当前候选版本；禁止连接 Labs，禁止使用宽泛的 `UPDATE` 或删除语句。

## 快照与停止门禁

1. 记录候选 SHA、当前应用镜像、服务状态、数据库和 Redis 健康、Outbox transport 配置和 Beat 最近触发时间。
2. 只读统计活动 `OpportunityCheckRun`、来源 `RUNNING`、`TaskRun running/retry_wait`、Outbox pending 和过期租约；只输出数量、稳定 ID、状态和错误码。
3. 数据库连接、备份、服务身份或对象归属无法确认时立即停止，不改变任何行。

## 招聘检查孤儿运行

1. 确认候选 Worker 健康、数据库连接正常，且没有第二个恢复批次。
2. 通过 `apps.opportunities.recover_check_leases` 执行一次有界恢复，不直接调用 adapter 或手工标记成功。
3. 读回 `TaskRun`、`OpportunityCheckRun` 和来源明细：租约清零，来源回到正确状态，领域运行进入正确终态，需要重试的任务已重新派发。
4. 复查没有过期活动租约、终态 TaskRun 绑定活动领域运行或失效活动运行被旧幂等键永久复用。
5. 发现未知任务、矛盾状态或无法归属行时停止并保留审计证据，不删除、不覆盖、不强制成功。

## Outbox 失败积压

`core.outbox_transport_failed.v1` 表示 transport 发布失败并进入重试，不等价于业务事件丢失。

1. 只读确认 transport 工厂、通知/邮件依赖、数据库、DNS/TLS 和网络出口；日志只记录脱敏错误码。
2. 读取失败事件数量、最早可用时间、尝试次数和租约状态，不读取正文、邮箱、token 或连接串。
3. 依赖恢复后使用现有 `publish_outbox`/`publish_batch` 入口执行一次有界重试。
4. 读回成功事件为 `PUBLISHED` 且租约为空；仍失败的事件保留稳定错误码交给既有重试和告警。
5. 无法证明外部副作用幂等、连续三次失败或出现重复通知时停止发布并升级人工审查。

## 恢复后的调度读回

1. 确认每分钟补偿任务和每日上海时间 18:00 任务已注册。
2. 不手动抓取来源；等待受控调度窗口或在隔离演练环境验证派发。
3. 记录恢复前后计数、任务 ID、错误码、Outbox 结果和通知去重结果，不记录正文、邮箱或凭据。

## 回退

恢复发现错误时，只停止候选 Worker/Beat 的进一步派发并回退应用镜像；本轮无数据库 migration，不执行反向迁移。备份、旧镜像和审计记录必须保留。
