# Kajspace 正式增量更新公告（候选）

状态：候选已完成代码与隔离验证，尚未执行正式数据库、镜像或服务操作。

本次候选以远端 `origin/main` 的 `82df3cc` 为基线，修复管理端和用户工作流中反馈消息使用固定 `0`、刷新后统计丢失，以及 Toast 遮挡顶部导航的问题。更新不新增数据库表或迁移，不改变现有账户、文章、招聘、题库、通知和媒体数据。

## 本次更新

- 统一使用全局反馈 Toast 展示登录、账户设置、文章、评论、导出、题库、通知、标签、分区、导航、招聘审核和作者工作流的成功反馈。
- 批量文档/题库处置只展示服务端传回且通过一致性校验的总数、成功数和失败数；缺失、非法或不一致时明确提示“统计暂不可用”，不再伪造 `0`。
- 导航删除、分区删除、标签恢复和招聘批量审核读取真实的重定向计数，并拒绝负数、超范围或无效值。
- HTMX 局部刷新完成后也会发现并消费 Toast 标记，避免只在首次整页加载时提示。
- Toast 位于全局顶部栏下方，窄屏下仍保留安全间距，不遮挡导航。
- 模板恢复标准 Django `request` 上下文，保证局部页面的查询状态和反馈参数由服务端提供。

## 数据与运行状态

本轮没有模型或 migration 变更，不需要导入 Labs 数据，也不需要重新抓取岗位或迁移题库。正式部署窗口仍需先检查并安全修正历史异常状态：招聘检查孤儿运行/过期租约，以及 `config.runtime_tasks.publish_outbox` 的 `core.outbox_transport_failed.v1` 失败积压。具体顺序见同目录的 `state-repair-runbook.md`。
