# 2026-08-25 Agent 与知识题库增量更新

状态：准备执行正式环境增量更新，尚未宣称生产切换完成。

## 更新范围

- 发布当前 Labs 基线后的站点、管理端、工作机会和答题中心代码。
- 应用 `agents`、`learning` 以及本轮其他待执行 migration；不反向迁移旧结构。
- 将当前管理员 Endpoint、两个 Agent Profile、对应 Prompt 修订和站点 Agent 配额配置迁移到正式库。自定义 API Key 不复制 Labs 密文，迁移脚本必须使用两端密钥重新加密后写入。
- 将唯一已批准知识文档、其媒体文件、题库系列和两卷已发布题库的修订、题目、知识点、标签与关联迁移到正式库。
- 不迁移生成失败的历史系列、运行中的 Invocation、TaskRun、token reservation 或 Labs 其他学习数据。
- 修正目标范围内的错误运行状态：正式库只接受发布态题库和批准态文档；失败/运行中 Labs 记录不进入正式库。

## 执行顺序

1. 核验候选提交、镜像、migration plan、生产账户映射和媒体 SHA-256。
2. 创建并读回正式 PostgreSQL 与媒体备份；记录归档路径、大小和 SHA-256。
3. 构建不可变候选 Web 镜像，运行 `check`、migration drift 和 readiness 检查。
4. 用候选镜像执行正式库 migration，读回 migration leaf 与关键约束。
5. 在事务内导入 Endpoint/Profile/Prompt、知识文档、媒体资产/绑定、发布题库及其依赖；完成后核对行数、外键、状态和 SHA-256。
6. 更新正式 runtime compose 的候选镜像引用，滚动重建 Web、Worker、Beat；不重建数据库或 Redis 卷。
7. 读回 Web/Worker/Beat 健康、公开题库、登录答题入口、媒体代理和管理 Endpoint 状态；确认没有持续 5xx 或静态资源 404。
8. 保留旧镜像和新鲜备份作为回退依据；应用健康失败时只恢复旧应用，数据库保持前向迁移。

## 不变量与停止条件

- 账户 ID 必须与正式库已有账户一一匹配；不创建或覆盖账户。
- Endpoint 的 API Key 明文不得出现在 SQL、日志、差异、通知或文档中。
- 知识文档媒体文件复制后，目标文件 SHA-256 和数据库记录必须与 Labs 一致。
- 两卷题目数、知识点覆盖/遗漏计数、标签关联和发布状态必须与 Labs 读回一致。
- 任一备份、migration、数据校验、候选健康或回退健康检查失败，立即停止后续切换并保留现场证据。
