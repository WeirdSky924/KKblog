# P0：正式环境低风险基线与金丝雀任务

状态：未执行

目的：在不制造明显业务压力、不调用真实 AGENT 额度、不触发招聘采集的前提下，确认正式环境的健康、延迟、静态资源、数据库连接、队列和可观测性基线。

## 1. 执行边界

- 目标环境：正式环境；只允许白名单测试 IP 和专用测试账户。
- 流量上限：建议从 1 个并发用户开始，逐步到 2、5 个并发；不进行持续高压。
- 持续时间：单场景 5 分钟，整轮不超过 30 分钟。
- 默认只读：不上传文件、不提交文章、不生成题库、不执行 AGENT、不启动招聘来源采集。
- 允许的写入：测试账号的登录会话、必要的访问统计和审计；测试完成后按账号范围清理。
- 停止条件：错误率升高、生产 p95 明显恶化、数据库锁等待、队列持续增长、容器重启、Provider 误调用或无法确认流量来源。

本任务对应执行日志：[p0-production-canary.execution.md](p0-production-canary.execution.md)。每次执行先生成唯一 `run_id`（建议 `P0-YYYYMMDD-HHMM-序号`），只在执行日志中追加真实结果；旧结果不得覆盖。

## 2. 前置任务

- [ ] 记录正式镜像、Git 提交、Compose 配置、迁移 leaf 和备份编号。
- [ ] 确认 Web、Worker、Beat、Caddy、PostgreSQL、Redis、Umami、Mailpit 健康。
- [ ] 确认监控面板、日志、trace、数据库 `pg_stat_activity` 和 Celery 队列可读。
- [ ] 创建或确认专用测试账户、测试 IP 白名单和回滚联系人。
- [ ] 明确本轮时间窗口、最大请求数和停止负责人。

前置锁定结果必须包含：测试提交/镜像摘要、数据快照时间、白名单来源、并发梯度、每个场景最大请求数、允许的错误预算和停止负责人。未锁定这些字段不得标记为“可执行”。

## 3. 执行任务

### P0-HTTP：边缘与页面基线

- [ ] `P0-HTTP-01`：`/health/live`、`/health/ready`。
- [ ] `P0-HTTP-02`：首页、登录页、作者主页、文章详情。
- [ ] `P0-HTTP-03`：找工作默认列表、岗位搜索、招聘类型/城市筛选、分页。
- [ ] `P0-HTTP-04`：静态 JS、CSS、字体和一张公开媒体文件。
- [ ] `P0-HTTP-05`：匿名权限入口：通知、知识、题库、收藏、管理员页面。
- [ ] 每个请求记录状态码、请求总耗时、服务端耗时（若可得）、响应大小、trace/请求标识和采样时间。

### P0-数据库与缓存基线

- [ ] `P0-DATA-01`：记录 PostgreSQL 活跃/空闲连接、锁等待、慢查询和事务时长。
- [ ] `P0-DATA-02`：记录 Redis 延迟、连接数、内存、命中率和阻塞客户端。
- [ ] `P0-DATA-03`：确认请求结束后连接数和事务数回落，不出现泄漏。
- [ ] `P0-DATA-04`：只读抽查岗位排序、搜索结果、文章分页和通知未读查询。

### P0-任务与容量基线

- [ ] `P0-RUN-01`：TaskRun running/pending/expired 数量。
- [ ] `P0-RUN-02`：Outbox pending、Consumer processing 数量。
- [ ] `P0-RUN-03`：OpportunityCheckRun 活动数量、RUNNING 来源数量和租约最近更新时间。
- [ ] `P0-RUN-04`：AgentInvocation/文章解释/题库生成活动数量。
- [ ] `P0-RUN-05`：媒体磁盘总量、可用量、容量状态和 inode。
- [ ] `P0-RUN-06`：Worker/Beat 重启计数和最近任务失败码。

## 4. 通过标准

- 所有探针返回预期状态码，错误率为 0；若出现业务已有 4xx，必须分类记录。
- p95 不超过发布前基线的约定增幅；不得出现持续增长的队列、连接、锁等待或内存。
- 测试结束后任务、连接、Redis 临时键和测试账号状态回落。
- 未调用真实 AGENT、未手动抓取招聘来源、未产生生产文件写入。

执行前必须在日志中填写具体阈值（例如允许的 p95 增幅、错误预算、队列回落时限），不能在看到结果后再倒推通过标准。每个未通过项都要关联证据和优化任务编号。

## 5. 后续路线

P0 通过后才进入 P1。若 P0 发现慢查询、连接泄漏、队列积压或错误状态，先建立优化任务和修复版本，不直接提高并发。
