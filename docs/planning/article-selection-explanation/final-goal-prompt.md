# 文章划词解释实现 Goal Prompt

你是 Kajspace 项目的主开发代理。请在 `/home/code/personal-blog` 维护源码，并将每个完成且验证通过的运行时切片按项目规则同步到 `/home/code/.codex-worktrees/personal-blog/labs-test-environment`，以 Labs 为唯一测试环境推进下面的目标。

## 目标

依据本目录的 [需求与设计](./design-plan.md) 和 [实施 Todo](./implementation-todolist.md)，按 `SE-001` 到 `SE-015` 的依赖顺序，完成登录用户在公开文章阅读页的“划词解释”能力，并用真实 Labs 用户流、隔离 PostgreSQL/Redis、现有 AGENT/TaskRun owner 和浏览器验证证明闭环可用。

完成时必须同时满足：

1. 登录用户在文章正文选中文本后可以请求中文解释；未登录用户完全看不到右下角入口、胶囊工具栏和选区解释按钮。
2. 右下角圆形按钮通过符合 Kajspace 现有克制 Swiss/编辑式风格的动画向左展开为文章底部中央的可扩展胶囊工具栏；工具栏与解释面板分离，后续工具可以复用同一 registry。
3. 选区只保留可解释的纯文本：图片、图片 alt、链接目标等不解释内容去除；表格、LaTeX、代码块转为普通文本；不执行代码、不访问链接、不调用工具、不发送整篇文章。
4. 服务端从公开文章真实 query 组装选区、文章标题、摘要、标签和当前一级标题；前端字段不能绕过文章可见性、权限、长度和字符校验。默认选区上限 1000 字，截断时在回复侧说明原始字数和实际处理字数。
5. 新增独立的 `article-selection-explanation` AGENT profile 和当前 Markdown Prompt，复用现有 Endpoint、Gateway、Prompt 快照、调用审计、token reservation、Markdown sanitizer 和错误 owner；不创建平行调用中心。
6. 本期不实现 SSE、ReadableStream、增量 token、流式配置或打字机效果。等待期间只显示真实加载状态；不得为了视觉效果伪造流式输出。文档审核和题库生成保持现有完整响应协议不变。
7. 管理后台“内容与互动”配置每日每用户解释次数、每分钟每用户解释次数、单次选区上限和每账户本地历史条数，默认分别为 `50/5/1000/30`。限制必须在创建 AGENT Invocation 前原子裁决；达到限制时不调用模型、不扣 token、不发通知，只在解释面板说明原因。
8. 每篇文章的手动授权只记住该文章；个人设置提供默认关闭的“自动接受文章划词解释” Switch。开启后跳过逐篇确认，关闭后恢复询问。授权和本地历史按登录账户隔离。
9. 所有文章共用一个按账户命名空间隔离的 `localStorage` 历史列表，每条显示文章 ID，保存成功、失败和已停止记录，最多保留配置数量，支持面板内清空。历史不能成为下一次 AGENT 的上下文，也不保存到服务端。
10. 解释请求复用现有 TaskRun、租约、幂等、取消、重试和 Reservation 机制。排队任务可取消；执行中的任务检查取消并阻止晚到结果发布；额度正确释放。只有上游异常、超时或网络失败显示一次重试，其他状态不显示重试。
11. 解释结果为中文安全 Markdown，Prompt 只对“简明解释、术语/缩写、语境/使用场景、不确定性”作软约束，不强制题库式结构 schema；输出仍必须经过现有安全 Markdown renderer，禁止原始 HTML、脚本、iframe、危险链接和工具动作。
12. 覆盖访客、普通用户、作者、管理员，文章公开/不可见状态，空选区、混合选区、超长多字节文本、限额边界、授权拒绝、停止、失败、重试、重复提交、晚到响应、损坏本地历史、账户切换、三种主题和 `390/768/1440` 视口。

## 必须保留的状态语义

解释请求至少区分：

- `CONSENT_REQUIRED`：当前文章尚未授权；
- `RATE_LIMITED`：每日或每分钟用户限制已达，零 AGENT 调用；
- `EMPTY_SELECTION` / `SELECTION_INVALID`：无可解释文本或输入非法；
- `PENDING`：任务已受理并等待/执行；
- `SUCCEEDED`：安全 Markdown 已返回并保存本地历史；
- `STOPPED`：用户主动停止，保存历史但不可重试；
- `FAILED_RETRYABLE`：上游异常，可重试一次或按现有重试上限处理；
- `FAILED_FINAL`：配置、权限、安全拒绝或重试耗尽，不显示重试。

禁止把限额拒绝伪装成成功、把取消伪装成完成、把上游错误伪装成空解释，或把半截模型响应保存为成功答案。

## 必须停止并向用户说明的情况

- 发现 owner、权限、文章可见性、token 结算、取消晚到结果或账户隔离无法安全闭合；
- 需要改变现有文档审核/题库 AGENT 协议，或需要直接启用流式而没有兼容合同；
- Labs 健康、热重载或受影响用户流失败，且一次定向恢复后仍无法验证；
- 需要生产/共享数据库写入、真实付费 Provider、Git 交付或超出当前授权的服务动作；
- 同一缺陷连续三次修复仍未解决，需重新检查架构和请求用户决策。

最终报告必须以事实为准，区分“代码已实现”“Labs 已验证”“文档已更新”和“生产/Git 尚未执行”，不得用静态检查或假数据替代真实闭环证据。
