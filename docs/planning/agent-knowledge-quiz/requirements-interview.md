- `CONFIRMED`：用户已明确提出或回答，不得静默改写。

- `PROPOSED`：为使规划闭环给出的建议默认值，尚未得到用户确认。
- `OPEN`：必须通过后续一问一答裁决；会改变 schema、权限、费用、外部暴露或判分的 OPEN 会阻止对应实现。

## 4. 第一优先级问题

这些问题会决定 owner、schema、秘密和模型调用边界，实施前必须先回答。

### Q001｜“附件权限”是否直接复用现有权限

状态：CONFIRMED（2026-08-15）。

裁决：直接使用现有 `attachment_upload_enabled`，不建立独立的“知识文档上传权限”。目前只有作者可被授予该能力；撤销作者角色时，知识文档上传能力随现有附件能力同步失效。

影响：`apps/accounts` 继续作为该权限的唯一 owner；`apps/learning` 只调用公开 capability，并在上传和提交审核时重新校验，不增加账户字段或平行授权页面。

### Q002｜AGENT 与 Endpoint 的数量关系

状态：CONFIRMED（2026-08-15）。

裁决：管理员可以维护多个 Endpoint，每个 AGENT 分别选择一个 Endpoint；多个 AGENT 可以复用同一个 Endpoint。审核 AGENT 与题库生成 AGENT 可以使用不同模型，也可以选择同一模型配置。

影响：`AgentEndpoint -> AgentProfile` 为一对多关系；Endpoint 的启停、模型或认证配置变更影响所有引用它的 AGENT，新业务运行必须固化 Endpoint 与模型快照，历史运行不随当前配置漂移。

### Q003｜模型认证信息如何提供

状态：SUPERSEDED（2026-08-18，改由 Q003A 统一裁决）。

历史裁决：Endpoint 可以选择“无需认证”或“服务器密钥引用”。真实 API Key 只配置在服务器 `.env`，管理页面不读取、不录入、不显示密钥，数据库只保存安全别名。

### Q003A｜自定义 Base URL 与 API Key

状态：CONFIRMED（2026-08-18）。

裁决：管理员需要支持 LangChain 风格的自定义连接配置：Provider、Model、Base URL 和 API Key。API Key 可以直接在 Endpoint 管理表单输入，但必须在服务端加密后保存；编辑时不回显明文，空输入保持原密钥，只有明确勾选清除才删除。仍保留服务器密钥别名模式，用户和业务模块不能读取或覆盖这些凭据。

影响：Endpoint 增加自定义 API Key 认证模式和加密密文；Invocation/EndpointCheck 固化加密凭据快照，Gateway 仅在外呼前解密到进程内短生命周期变量。明文不得进入数据库、审计、通知、错误、日志、模板、备份导出或普通 DTO；密钥轮换只影响后续新调用，旧调用继续使用已固化快照。Base URL 仍执行 HTTPS、SSRF、DNS rebinding 和重定向防护。

### Q004｜模型协议与自建网络范围

状态：CONFIRMED（2026-08-15）。

裁决：首版支持 GPT、Claude、DeepSeek。采用网络方案 1：公网 Endpoint 默认只允许 HTTPS；`localhost` 或内网自建端点必须先在服务器 `.env` allowlist 中登记，登记后可使用 HTTP。

影响：`apps/agents` 提供 GPT/OpenAI-compatible、DeepSeek/OpenAI-compatible 与 Claude/Anthropic Messages adapter，并向业务层暴露同一个结构化调用 port。Base URL 仍执行 SSRF、DNS rebinding 和重定向防护；云元数据、链路本地等保留地址不能通过普通 allowlist 放开。

### Q005｜知识文档大小和长文策略

状态：CONFIRMED（2026-08-15）。

裁决：单个 Markdown 最大 `2 MiB`，系统按 Markdown 标题、列表和段落边界自动分块。每个 Endpoint 配置上下文窗口和单次业务任务总 token 上限；整份文档超过总预算时，在模型调用前拒绝。

影响：审核和生成都必须覆盖全部分块并做全局汇总；任一审核分块拒绝则整份文档拒绝，生成阶段必须跨分块去重。不能因达到 token 预算就静默截断，也不能把部分题目发布为完整题库。

### Q006｜已通过知识文档谁可以查看

状态：CONFIRMED（2026-08-15）。

裁决：上传者和管理员可以查看原始知识文档全文，但只有上传者可以使用自己的已通过文档生成题库。其他登录用户和访客不能查看或下载原始 Markdown，公开题库也不暴露源文档。

影响：learning 提供 owner 与 administrator 两种受控详情读取，列表不预取正文；生成 service 必须要求 `document.owner_id == actor_id`，管理员身份不获得代生成例外。管理员正文访问遵循 Q032：写具体 actor 审计，owner 只见时间/用途历史且不收实时通知。

### Q007｜审核通过后是否还需人工审核

状态：CONFIRMED（2026-08-15）。

裁决：文档通过审核 AGENT 后自动进入已通过文档库；生成题库通过固定 schema、业务约束和安全渲染校验后自动公开，不设置管理员发布前审核。

影响：管理员保留事后隐藏、恢复和删除能力。模型拒绝、调用失败、分块未完整处理、schema 不合法或确定性门禁失败都不能自动通过；上传授权与公开声明仍由 Q030 补齐。

### Q008｜简答题如何判分

状态：CONFIRMED（2026-08-15）。

裁决：用户提交简答答案后，系统展示参考答案和评分要点，由用户选择“已掌握”或“未掌握”。简答题不计入自动客观分，自评结果决定是否进入错题本。

影响：不新增简答评分 AGENT，不产生答题阶段模型费用。结果页分别显示客观题自动得分和简答题掌握数量；QuizResponse 保存用户答案、参考答案快照与自评状态，以便历史可解释。

### Q009｜外部 API 是否需要凭据

状态：CONFIRMED（2026-08-15）。

裁决：管理员开启外部 API 后，任何人都可以匿名执行只读 GET，请求按客户端 IP 限流；不签发或要求 API Key。

补充权限裁决：公开 API 只读取公开题库，不提供 AGENT 写能力。知识文档上传、整理和转题库要求账户当前具备现有附件权限；所有登录用户均可进入答题界面、保存答题记录和使用错题本，不要求附件权限。

补充配置裁决：模型 Endpoint、Model、AGENT、Prompt 以及外部题库 API 开关都只由管理员设置。有附件权限的用户不配置或选择 API/模型，也不读取任何密钥，直接使用管理员为知识审核和题库生成启用的 AGENT。

影响：API 限流 key 使用可信代理解析后的客户端 IP，Redis 只作计数优化且不能改变题库可见性。服务端 upload/organize/generate 分别复核 `attachment_upload_enabled`，再按稳定用途获取管理员启用的 profile；用户请求不能传入 endpoint/model/prompt/secret。quiz/record service 只要求有效登录会话和本人对象权限。

### Q010｜API 是否返回正确答案与解析

状态：CONFIRMED（2026-08-15）。

裁决：列表接口只返回题库元数据；指定题库详情接口返回完整题目、正确答案、简答参考答案/评分要点和解析。

影响：API 不返回原始知识文档、Prompt、Endpoint、Model、审核内部信息或调用记录。答案与题面共享题库可见性和缓存失效规则，题库隐藏/删除或全局 API 关闭后不能通过独立缓存继续读取答案。

## 5. 第二优先级问题

### Q011｜右上角上传入口的准确位置

状态：CONFIRMED（2026-08-15）。

裁决：在现有右上角账户浮窗中增加“知识文档”入口，仅对当前有附件权限的用户显示；点击进入独立“我的知识文档”页面，在页面中完成上传、整理和转题库。账户浮窗内不直接放上传表单。

影响：复用现有 personal menu 和 capability presentation；服务端仍重新授权。顶部答题入口保持独立并面向所有登录用户，不把文档管理与答题导航混成一个入口。

### Q012｜一个文档能生成多少题库

状态：CONFIRMED（2026-08-15）。

裁决：同一份已通过文档可以按不同题型配置生成多个独立题库。每次生成创建不可变初始修订；后续人工修正按 Q015 创建新修订，不覆盖旧修订或既有答题记录。

影响：QuestionBank 是独立聚合而不是文档的一对一当前指针；重复生成使用新 ID 和幂等键。账户配额、并发限制和每日生成上限负责防滥用，具体数值在容量设计中确定。

### Q013｜题量与题型数量

状态：CONFIRMED（2026-08-15）。

裁决：用户只勾选允许生成的题型，不填写题数或比例。生成 AGENT 必须先分析整份知识文档，形成可考查知识点清单，再为每个知识点生成题目，并在已开启题型中自行决定题型分布。单次最大题数由管理员设置。

影响：生成 schema 需要显式知识点清单和题目覆盖引用，服务端验证全部文档分块、知识点覆盖、题型白名单和管理员上限；生成运行固化当时的上限。知识点数量超过上限时的处理方式由 Q013A 裁决。

### Q013A｜知识点数量超过管理员题数上限

状态：CONFIRMED（2026-08-15）。

裁决：先把相关知识点合并为综合题，尝试在管理员设置的单卷上限内覆盖全部知识点。若仍无法覆盖，则降级为重要度截取与分卷的组合：第一卷生成上限内的重要知识点，剩余知识点进入第二卷，最多只允许一个额外分卷。第二卷达到上限后仍超出的知识点可以舍弃，最终必须提醒并说明覆盖与遗漏情况。

影响：一次生成请求建立 QuestionBankSeries，包含一卷或最多两卷；管理员上限按单卷计算。系列保存 total/covered/omitted 计数、每卷覆盖引用和遗漏引用，结果页明确显示。降级只适用于知识点容量溢出；Provider/安全/schema 失败仍是失败，不能发布部分卷。

### Q014｜题库标题、简介和标签的编辑权

状态：CONFIRMED（2026-08-15）。

裁决：用户生成前填写必填的题库基础标题和可选简介；AGENT 自动生成标签并优先复用已有标签。发布后上传者和管理员都可以修改标题、简介和标签。

影响：标题/简介/标签属于 QuestionBankSeries 的可变元数据，使用 row version 防并发覆盖，不修改不可变题目或历史答题。两卷共用基础标题，展示时自动追加“第一卷”“第二卷”。标签使用 Q016 确认的独立题库标签目录。

### Q015｜生成题目能否人工编辑

状态：CONFIRMED（2026-08-15）。

裁决：上传者和管理员都可以修正生成后的题目。每次保存创建新的完整不可变题库修订，校验成功后公开页原子切换到新修订；旧修订不覆盖、不删除。

影响：QuestionBank 持有 current revision 指针，QuestionBankRevision/Question 保存不可变历史。QuizAttempt 固定开始时的 revision；管理员修订写审计，上传者和管理员修订都记录 editor/reason。局部编辑提交时仍需整卷 schema、答案、覆盖和 Markdown 安全校验。

### Q016｜题库标签是否复用文章标签

状态：CONFIRMED（2026-08-15）。

裁决：建立独立的题库标签目录。AGENT 生成标签时只在已有题库标签中优先复用，不复用文章标签。

影响：`apps/learning` 独占 QuestionBankTag 及系列关联；`apps/content` 继续独占文章标签。两套标签不共享主键、审核、删除、统计或使用计数生命周期，题库搜索与筛选只查询题库标签。

### Q017｜多选题部分得分

状态：CONFIRMED（2026-08-15）。

裁决：多选题不提供部分得分。用户答案必须包含全部正确选项且不包含任何错误选项才得满分，否则为 `0` 分。

影响：服务端把选项 ID 规范化为集合后做严格相等判断，选择顺序不影响结果；不保存或展示部分分、扣分或负分。该结果同时驱动客观题得分与错题本写入。

### Q018｜抽题和选项顺序

状态：CONFIRMED（2026-08-15）。

裁决：开始答题前提供相互独立的“随机题目”和“随机选项”Switch，由用户为本次答题自行选择。

影响：随机题目关闭时按题库 revision 的固定顺序取前 N 题，开启时随机抽取并排列 N 题；随机选项只打乱单选和多选的选项。创建 QuizAttempt 时必须保存两个开关的配置快照、题目 logical ID 顺序和每题选项顺序，刷新或跨设备续答不重新随机。默认开关状态由 Q018A 确认。

### Q018A｜随机开关默认状态

状态：CONFIRMED（2026-08-15）。

裁决：“随机题目”和“随机选项”进入答题配置页时默认都开启，用户可在本次开始前分别关闭。

影响：前端默认值和服务端缺省配置都使用 `true/true`，不能依赖仅由客户端补齐的隐式默认；QuizAttempt 仍保存用户提交后的实际值。

### Q019｜限时配置与超时结果

状态：CONFIRMED（2026-08-15）。已通过 Q019A-Q019C 确认默认状态、可选时长和软超时处理。服务端提醒阈值一旦创建便持续计算，断线、关闭页面或换设备都不能暂停或延长。

### Q019A｜计时 Switch 默认状态

状态：CONFIRMED（2026-08-15）。

裁决：计时 Switch 默认关闭，答题默认不限时；用户主动开启后才选择时长。

影响：计时关闭时服务端保存 `deadline_at = null`，并忽略客户端可能残留的隐藏时长字段。只有开启计时且时长通过服务端校验时才创建截止时间；断线、关闭页面或换设备仍不暂停已开始的计时。

### Q019B｜可选时长和默认时长

状态：CONFIRMED（2026-08-15）。

裁决：计时开启后只能从 `10、20、30、60、90、120` 分钟的固定菜单中选择，初始选中 `30` 分钟，不提供任意数字输入。

影响：客户端显示选项菜单，服务端以相同白名单校验 `duration_minutes`，不能只信任前端限制。QuizAttempt 同时保存选择值和由服务端计算的绝对 `deadline_at`。

### Q019C｜超时处理

状态：CONFIRMED（2026-08-15）。

裁决：到达计时阈值后只显示超时提醒，仍允许用户继续答题和手动提交；不自动提交、不锁定答案、不把 attempt 转为结束状态。

影响：`deadline_at` 是软提醒阈值而非拒绝写入的硬截止时间。超过阈值后服务端继续接受该 attempt 的答案保存和幂等手动提交，最终照常判分并更新错题本；`started_at`、`deadline_at`、`submitted_at` 可以读回实际用时和是否超时，不需要独立的强制提交任务。

### Q020｜答题过程中是否保存进度

状态：CONFIRMED（2026-08-15）。

裁决：选择题答案变更后立即自动保存到服务器；简答题在停止输入后防抖保存。用户可以刷新、退出后恢复，并可在其他设备继续同一未完成答题。

影响：服务器是进度事实源，QuizResponse 保存草稿答案、row version 和最后保存时间。并发设备更新必须携带版本，过期版本返回冲突和最新值，不能静默覆盖；已提交 attempt 不再接受答案修改。自动保存不判分、不更新错题本、不返回正确答案，最终手动提交才产生结果。

### Q021｜错题何时视为已掌握

状态：CONFIRMED（2026-08-15）。

裁决：错题只能由用户在错题本中手动标记为“已掌握”；答对不会自动改变掌握状态。用户也可以手动把已掌握题目恢复为“待复习”。

影响：WrongQuestion 把不可丢失的错误/正确统计与用户控制的 `TO_REVIEW`/`MASTERED` 展示状态分开保存。后续答对、答错和简答自评只更新统计，不自动隐藏、恢复或删除错题；默认错题列表隐藏 `MASTERED`，但历史和已掌握筛选仍可读。

### Q022｜“管理答题记录”的具体动作

状态：CONFIRMED（2026-08-15）。

裁决：用户可以查看详情和筛选自己的答题记录，并支持删除单条、复选批量删除、清空全部和导出 CSV。

影响：所有 query 和 mutation 都由服务端限定为当前账户；批量删除/清空先显示精确数量并二次确认。CSV 按每道作答一行展开本人可见快照，使用有界流式导出并防止表格公式注入。删除是软删还是物理删及冷静期由 Q024 裁决；与错题统计的关系由 Q022A 裁决。

### Q022A｜删除答题记录是否影响错题统计

状态：CONFIRMED（2026-08-15）。

裁决：答题记录与错题本作为两类独立学习数据保存。删除单条、批量删除或清空答题记录后，WrongQuestion 保持不变。

影响：记录删除流程不得重算或删除错题的答错/答对次数、时间和手动掌握状态。错题只由完成答题的幂等更新以及用户显式的掌握/恢复操作改变；账户级彻底删除时两类数据仍按 Q024 的统一个人数据生命周期处理。

### Q023｜题库 owner 的管理能力

状态：CONFIRMED（2026-08-15）。

裁决：题库上传者可以隐藏、重新公开，并发起删除自己的题库；管理员保留相同操作和强制管理能力。

影响：QuestionBank 公开状态区分 `OWNER_HIDDEN` 与 `ADMIN_HIDDEN`。owner 可以恢复自己隐藏的题库，但不能解除管理员强制隐藏，也不能通过新修订绕过；管理员强制操作写审计并通知 owner。删除冷静期与最终清理由 Q024 裁决。

### Q024｜删除与保留周期

状态：CONFIRMED（2026-08-16）。已通过 Q024A-Q024D 确认用户主动删除冷静期、失败材料保留、源文档/题库/历史关系和账户彻底删除清理。

### Q024A｜用户主动删除的冷静期

状态：CONFIRMED（2026-08-15）。

裁决：用户主动删除自己的知识文档、题库或答题记录时，统一进入 `7 天`软删除期。对象立即从正常列表、公开查询和新的业务入口隐藏，期间可撤销，期满后才进入最终清理。

影响：对象保存删除前状态、`deletion_requested_at` 和 `purge_after`。撤销恢复删除前状态，不能借删除/恢复解除 `ADMIN_HIDDEN`；期满清理由有界后台任务调用 owner service 与 media 清理端口完成。答题记录进入软删除不改变 WrongQuestion。

### Q024B｜被驳回文档和失败运行的自动保留期

状态：CONFIRMED（2026-08-15）。

裁决：`REJECTED`/最终 `REVIEW_FAILED` 知识文档和最终失败审核/生成运行的完整失败材料保留 `30 天`，供用户查看原因和重试；到期后清理原始失败内容与运行细节，只保留不含正文的状态、时间、对象 ID 和原因码，直到账户数据彻底清理。

影响：失败材料保存独立 `purge_after`，到期清理幂等解除 media 绑定和详细运行快照；最小 tombstone 不包含知识正文、Prompt、题目、答案或原始路径。生成失败只清理该次运行材料，不能级联删除仍有效的 `APPROVED` 源文档。用户在 30 天内主动删除时仍先遵守 Q024A 的 `7 天`可撤销期。

### Q024C｜源文档、题库与学习历史的删除关系

状态：CONFIRMED（2026-08-16）。

裁决：源知识文档、题库和用户学习历史采用相互独立的删除生命周期。删除源文档不影响已生成题库；删除题库后立即停止公开展示、API 读取和新答题，冷静期后清理题库本体，但既有答题记录与错题保留自包含快照供查看。已删除题库的错题不能再发起练习。

影响：QuizAttempt/QuizResponse/WrongQuestion 保存足以解释历史的题库标题、题面、选项、答案/参考答案和解析安全快照，题库最终清理时允许相关外键置空。HTML/API 公共 query 和缓存从删除请求开始即排除题库；历史详情和错题只读快照仍限本人。删除源文档仅移除原文与生成入口，题库保留无正文 provenance ID/owner 快照。

### Q024D｜账户彻底删除时的清理关系

状态：CONFIRMED（2026-08-16）。

裁决：账户达到彻底删除阶段时，清理该账户的原始知识文档、失败材料、所拥有题库、本人答题记录和错题，题库停止公开。其他用户已经产生的答题/错题快照继续保留，但作者显示为“已注销用户”且不保留可识别账户信息；最小安全审计同样不得包含个人标识。

影响：learning 接入 accounts 的彻底删除协调入口，以幂等、有游标、可重试的清理 service 完成本人数据删除和公共/API 缓存失效，不再叠加子对象冷静期。其他用户的历史快照置空 owner/bank/question 引用、清除作者 ID/显示名并禁用练习，只保留题目与作答解释所需内容。审计仅保留不可反向关联的事件类型、结果、计数和时间桶。

### Q025｜重复文档处理

状态：CONFIRMED（2026-08-16）。

裁决：同一账户内按规范化内容 SHA-256 去重。已有未清理文档时阻止重复上传并引导到原记录；原记录处于软删除期时提示恢复。不同账户可以独立上传相同内容，系统不暴露跨账户重复信息。

影响：摘要输入只做 UTF-8 BOM 去除和换行统一，不裁剪或折叠可能改变 Markdown 语义的字符。同一 owner 的未清理摘要使用条件唯一约束处理并发；有效文档复用原入口，驳回/失败文档引导查看或重试，`CONTENT_PURGED/DELETED` 后允许重新上传。跨账户不复用业务对象、审核结论或媒体绑定，也不返回碰撞信号。

影响：终态事务通过现有 Outbox 发布版本化事件，通知按 event/recipient/template 幂等，Task 重试不重复发送。通知只包含安全终态、稳定原因或覆盖计数和本人可访问链接，不包含文档、Prompt、题目/答案、模型输出、路径或密钥。部分覆盖通知明确 total/covered/omitted；不创建平行通知或 outbox。

### Q035B｜外部 API 匿名 IP 限流

状态：CONFIRMED（2026-08-16）。

裁决：每日上传 `1–100`、同时待处理 `1–20`、每日生成 `1–50`、同时模型任务 `1–3`、未清理题库 `1–2000`。

影响：全局默认和账户覆盖使用相同服务端范围校验，拒绝 0、负数和越界值。需要完全禁用某账户时撤销附件能力，不使用 0 配额创建第二套权限语义。配置更新继续使用 row version 和审计。

### Q036D｜全站与 Endpoint 模型用量保护层级

状态：CONFIRMED（2026-08-16）。

裁决：必须同时配置全站每日 token 上限和每个 Endpoint 每日 token 上限；每次调用前按最大可能用量预留，完成后按实际用量结算。金额只做可选估算展示，不作为强制门禁，以兼容自建模型。

影响：运行以幂等 reservation 同时占用全站/Endpoint 自然日 ledger，任一不足都在调用前进入可重试配额阻塞。可信 usage 用于结算并释放差额；usage 缺失时保留保守估算。预留支持租约/崩溃回收且配置降低不取消已预留运行。Endpoint 价格字段可空且只向管理员展示。默认值和硬范围由 Q036E 确认。

### Q036E｜每日 token 上限默认值与硬范围

状态：CONFIRMED（2026-08-16）。

裁决：全站默认 `5,000,000` token/日，可配置 `100,000–100,000,000`；单 Endpoint 默认 `2,000,000`，可配置 `50,000–50,000,000`，并要求 Endpoint 上限不大于全站上限。管理员要求设置重置选项。

影响：配置 service 同时校验硬范围与 endpoint <= site；降低全站值导致现有 Endpoint 越界时拒绝整次保存并返回冲突列表，不静默修改。默认值用于新建配置；重置入口遵循 Q036F 已确认的两个独立动作。

### Q036F｜模型用量设置的重置选项

状态：CONFIRMED（2026-08-16）。

裁决：提供“恢复默认上限”和“重置今日 token 已用量”两个独立按钮。重置用量不清除正在运行任务的预留，也不重置账户上传/生成次数；操作需要二次确认并追加审计调整记录。

影响：恢复默认值仍执行 Endpoint <= 全站交叉校验。用量 reset 追加不可变 adjustment 而非删除 ledger；全站 reset 同步处理各 Endpoint 已结算贡献，单 Endpoint reset 同步冲减其全站贡献，活跃 reservation 保持不变且继续占额度。操作记录 actor/reason/before/after，使用 row version 和幂等键。

### Q037｜管理端批量操作范围

状态：CONFIRMED（2026-08-16）。

裁决：只对管理员明确勾选的知识文档/题库提供批量隐藏、恢复或进入删除流程，显示精确数量并二次确认。申诉必须逐条阅读和决定，原文不能批量打开；不提供当前页或全部筛选结果一键处理。

影响：批量预检和执行都携带显式稳定 ID 集、状态分布与 row version，有界执行并返回逐项成功/失败，不能把部分成功包装为整体成功。服务端不得把分页/筛选条件重新展开为更大目标集；原文 access audit 和申诉决定继续逐对象处理。

### Q038A｜Endpoint 运行参数来源

状态：CONFIRMED（2026-08-16）。

裁决：上下文窗口、单次输出上限、单业务运行 token 预算、请求超时和并发上限都由管理员显式配置；表单提供安全默认值和硬范围。连通性检查只验证连接，不自动修改参数。

影响：不建立按模型名猜测或 Provider 自动探测后回写的平行事实。Endpoint 保存统一运行参数 schema/交叉校验；每次 invocation 固化 Endpoint row version 与参数快照，配置变更不漂移在途运行。默认值和范围由 Q038B 确认。

### Q038B｜Endpoint 运行参数默认值与硬范围

状态：CONFIRMED（2026-08-16）。

裁决：上下文默认 `131072`、范围 `4096–2000000`；单次输出默认 `8192`、范围 `256–131072`；单业务运行默认 `500000` token、范围 `10000–5000000`；请求超时默认 `120` 秒、范围 `10–600`；并发默认 `1`、范围 `1–5`。这些参数都允许管理员在每个 Endpoint 上单独配置，默认值只用于新建初始值。

影响：Endpoint 新增/编辑表单展示全部参数，管理员可在硬范围内修改；统一 schema 还要求 max output < context、估算 input + output <= context、per-run >= max output 且 per-run <= Endpoint daily。Endpoint 保存和 Gateway 调用前均校验；默认值与 Q036E 的 Endpoint daily `2,000,000` 兼容。连接检查和模型名变化不修改参数，invocation 保存完整快照。

### Q039｜API 限流计数存储不可用时的降级

状态：CONFIRMED（2026-08-16）。

裁决：Redis 无法提供匿名 API 限流计数时，外部 API 暂时拒绝请求，返回 JSON `503/rate_limiter_unavailable` 和短 `Retry-After`，不进入题库查询；站内 HTML 不受影响，持续故障按现有运维规则通知管理员。

影响：API limiter fail closed，不回退 PostgreSQL、进程内计数或无限放行；响应使用 `Cache-Control: no-store`。故障与恢复需要去重观测，恢复后无需数据迁移即可继续 Redis 原子限流。HTML transport 仍直接使用 public query，不依赖 API limiter。
